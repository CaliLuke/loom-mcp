# Context compaction: execution plan

Status: plan for design revision 8 of
[`context_compaction.md`](context_compaction.md), 2026-10-09. Nothing here is
implemented. The design holds the architectural contract: guarantees P1–P7
(design 4.1), mechanisms and decisions. This plan holds the tickets, their
order and their acceptance proofs, so the contract can stay stable while the
plan changes.

The acceptance proofs are binding: a ticket is done when its proof passes as written, and a proof is changed only by changing the design first.

One commit per ticket. Each ticket updates `docs/` and the repo skill for any
user-facing change, bumps `WorkflowProtocolVersion` and adds a replay test if
it changes workflow code. Each ticket lands with its acceptance proof as
failing-first tests, including the structural scenarios; nothing waits for
K19.

the eligible-evidence and server-only split that P4 relies on; P4's proof lands in K15. Valuable alone: the
full run becomes consultable and the 1 MB and history-growth failures go away.

module in step and adds a Go test for the invariant: K6, K7, K11, K12, K14
and K15 for `ContextCompaction.tla`; K7 for `StepPayload.tla`; K8 for
`CallCommit.tla` and `RequestRecord.tla`; K13 for `RecallDiscovery.tla`; K14
for `OverflowGuard.tla`; K18 for `SessionContinuation.tla` and
`ContinuationCarry.tla`. `make context-model-test` passes in every ticket
that touches a modelled rule (design 8).
