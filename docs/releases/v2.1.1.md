Loom-MCP {{version}} moves the framework baseline from Loom v1.10.0 to the
stable **Loom v1.12.0**. Loom-MCP APIs, generated code, and runtime behavior are
unchanged from **v2.1.0**, and the workflow protocol stays at 21, so running
workflows do not need to be drained for this upgrade.

## What the new Loom baseline brings

Services built with Loom-MCP can now use the Loom features released since
v1.10.0:

- **Per-key rate limiting.** `admission.KeyedRate` keeps a bounded token bucket
  per tenant or trusted peer, and `http/middleware.RateLimit` accepts custom
  rejection responders, including an RFC 9457 problem response.
- **OpenTelemetry setup.** `observability/otel.New` can export over OTLP gRPC,
  accepts full endpoint URLs, and lets each signal extend its pipeline. The new
  `slogbridge` package sends standard `log/slog` records to the OpenTelemetry
  Logs API with trace correlation.
- **`loom vet` fixes.** HTTP 5xx errors no longer need `Fault()`, and a declared
  `Retry-After` header counts as retry guidance for 429, 502, and 503 errors.

See the Loom [v1.10.1](https://github.com/CaliLuke/loom/releases/tag/v1.10.1),
[v1.11.0](https://github.com/CaliLuke/loom/releases/tag/v1.11.0), and
[v1.12.0](https://github.com/CaliLuke/loom/releases/tag/v1.12.0) release notes
for details.

## Upgrade

Use **Go 1.27.4 or later** and **Loom v1.12.0**, then regenerate so each
`gen/loom.json` records the new Loom version:

```sh
go install github.com/CaliLuke/loom/cmd/loom@v1.12.0
go get github.com/CaliLuke/loom@v1.12.0 github.com/CaliLuke/loom-mcp/v2@{{version}}
loom gen <module-import-path>/design
```

Loom-MCP's runtime and generated code do not use the Loom packages below. The
upgrade still moves your application to Loom v1.12.0, so check your own code if
it imports them directly:

- **Trace propagation.** With nil `Propagators`, `HTTPMiddleware`,
  `WrapHTTPClient`, and the gRPC options now use the global propagator instead
  of a fixed W3C TraceContext and Baggage propagator. A service that never calls
  `loomotel.New` or `otel.SetTextMapPropagator` stops propagating trace context
  without an error. Register a propagator at startup, before you build the
  instrumentation, or pass `Propagators` explicitly.
- **Global propagator.** `loomotel.New` now sets the global propagator on every
  successful call. To keep a propagator that you registered earlier, pass
  `Propagators: otel.GetTextMapPropagator()`.
- **Exporter endpoints.** `loomotel.New` rejects an `Endpoint` that has a scheme
  or a path at startup. Use a bare `host:port`, or move the full URL to
  `EndpointURL`.
- **Client span names.** `WrapHTTPClient` spans with a non-empty `ServiceName`
  are now named `GET <ServiceName>` instead of `HTTP GET`. Update dashboards,
  alerts, and sampling rules that match the old name.
- **Rate-limit middleware.** `middleware.RateLimit` takes variadic options.
  Existing calls compile unchanged; update any variable that stores the function.
- **Removed packages.** Loom v1.11.0 removed `observability/otel/logrusbridge`;
  move to `slogbridge`. Loom v1.10.1 removed the `server-error-fault` vet rule
  and the `vet.RuleServerErrorFault` constant; drop any references to them.

The [dependency guide](https://github.com/CaliLuke/loom-mcp/blob/{{version}}/docs/dependencies.md)
records the current baseline.
